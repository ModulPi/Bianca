# Bianca — 产品需求文档（PRD）

> 版本：v0.5 | 日期：2026-10-11 | 阶段：概念验证（PoC） | 状态：**PoC 需求已确认 ✅；v0.5 新增的目标驱动方向边界已确认 ✅（§2.4，2026-10-11）**

---

## 1. 产品概述

### 1.1 产品定位

Bianca 是一个**面向 C 端用户的加密货币自动交易 Agent 平台**，基于币安（Binance）交易所，帮助用户通过 AI Agent 辅助的自动化交易策略实现数字资产管理。

**PoC 聚焦：** 在币安 **Demo 现货** 环境上，由 **LLM 自主决策** 完成至少一次 **买入 → 卖出** 闭环。

**MVP 及后期：** 扩展策略模板、半自动模式、Web 控制台、合约品种与完整风控。

**v0.5 新增方向（目标驱动）：** 用户以**对话**方式给出一个**交易目标**（如"1000 USDT 试水，两周做到 1100，最多亏 5% 就停"），由**经理 Agent** 理解目标、拆解任务、指挥手下的子 Agent（行情 / 分析 / 风控 / 执行）执行，并持续判断"离目标还差多少"，直到达成、放弃或到期。详见 §2.4 与[经理 Agent 与对话层设计文档](outline-design/模块设计/经理Agent与对话层设计-Bianca.md)。

### 1.2 目标用户

| 用户画像 | 特征 | 核心诉求 |
|----------|------|----------|
| 初级散户 | 交易经验 < 1 年，资金量小 | "帮我自动赚钱，不用盯盘" |
| 进阶玩家 | 有一定交易经验，有自己的策略思路 | "把我的策略交给 Agent 自动执行" |
| 跟单用户 | 不想自己分析，愿意跟随信号 | "跟着高手/信号走" |

> **PoC 阶段：** 仅开发者本人本地使用（`localhost`），无多用户、无注册登录。

### 1.3 核心价值主张

- **Agent 自主决策（PoC 核心）：** LLM 分析行情，自主产出买/卖/持有信号
- **目标驱动（v0.5 方向）：** 用户给定一个有判据的交易目标，经理 Agent 自主拆解、指挥子 Agent 执行并追踪进度 —— 区别于"给参数跑策略"，这里给的是一段意图
- **可配置执行模式：** 用户可选择 AI 建议「自动执行」或「仅记录不执行」（PoC 默认自动执行）
- **风险可控：** 内置最小风控，PoC 验证后再扩展
- **透明可审计：** 每笔交易的决策过程可回溯
- **LLM 可切换：** PoC 默认 DeepSeek API；后期通过配置切换至本地 Ollama

## 2. 阶段边界（PoC / MVP / 后期）

### 2.1 PoC — 必须交付

| 项 | 范围 |
|----|------|
| **交易所** | 币安 Demo 现货（`demo-api.binance.com`） |
| **决策模型** | **LLM 自主：** Analysis Agent 分析行情 → 产出 BUY/SELL/HOLD → 风控 → 执行 |
| **Agent 编排** | LangGraph Supervisor 模式 |
| **闭环目标** | Agent 自主完成至少 **1 次买入 + 1 次卖出** |
| **LLM** | 默认 **DeepSeek API**；通过 `LLM_PROVIDER` 配置切换至 Ollama；支持「AI 建议自动执行」 |
| **执行模式** | 仅 **全自动**（半自动放 MVP） |
| **风控** | **最小 2 条：** 单笔金额上限 + 日亏损熔断 |
| **基础设施** | SQLite + 内存/文件缓存；Docker 仅跑 API 服务 |
| **界面** | CLI / curl 调 API，**无 Web 前端** |
| **安全** | API 仅绑定 `127.0.0.1`，PoC 不加鉴权 |
| **持久化** | SQLite 存交易日志、决策记录、Agent 状态 |

### 2.2 MVP — PoC 之后

| 项 | 范围 |
|----|------|
| **界面** | React + TypeScript 完整 Web 控制台 |
| **执行模式** | 增加 **半自动**（AI 建议 → 用户确认 → 执行） |
| **策略** | 策略模板引擎（网格、DCA、趋势跟踪） |
| **品种** | 现货 + U 本位合约 + 币本位合约 |
| **风控** | 完整 8 条规则 + 熔断状态机 |
| **基础设施** | PostgreSQL + TimescaleDB + Redis + Docker Compose 全套 |
| **LLM** | 分析报告 + 可选自动执行；支持云端 LLM 切换 |
| **通知** | Telegram / 邮件告警 |
| **模拟门禁** | 模拟交易验证达标后才允许切换实盘 |

### 2.3 后期（P2）

策略回测、策略市场、多交易所、移动端、信号跟单、社交交易、国际化。

### 2.4 目标驱动与经理 Agent（v0.5 新增，边界已确认 ✅，实现未开工）

> 完整定义见[经理 Agent 与对话层设计文档](outline-design/模块设计/经理Agent与对话层设计-Bianca.md)（v0.2）。四条能力边界已于 2026-10-11 拍板，见该文档 §7 的 ADR-018~022。

| 项 | 方向 |
|----|------|
| **交互方式** | 用户与**经理 Agent** 对话，用自然语言给出交易目标；经理解析为结构化目标并**复述确认**，用户可修正（ADR-020） |
| **执行主体** | 经理 Agent 拆解目标 → 指挥子 Agent（行情 / 分析 / 风控 / 执行）→ 汇总结果 → 判断进度 → 再决策 |
| **授权级别** | **全自动**：经理全权负责交易，不设人工闸门；授权随目标一次性固化（ADR-018） |
| **风控边界** | 风控参数仅可在目标确认时一次性授权，**执行期间不可修改**（ADR-021） |
| **可归因性** | **硬需求**：每笔交易必须能回答"为什么 / 当时看到什么 / 当时手里有什么"，用于事后归因与迭代优化（ADR-019） |
| **判定标准** | 从"有没有产生订单"（PoC）升级为"**目标有没有达成**"：达成 / 破线中止 / 时间窗到期 |
| **职责边界** | 子 Agent 保持确定性、可审计；不确定性只留在经理层；风控仍是必经节点（ADR-006 不变量不变） |
| **交互载体** | 先只做 CLI/HTTP，不做 Web 前端（ADR-022） |

**ADR-018 与 ADR-019 是一对，不可拆开执行：** 全自动意味着没有人能在事前拦下错误的交易，可归因记录是唯一的事后手段。设计文档 §2.4 已核实**现状三条判据全不满足**（`save_signal` 丢弃整份行情快照、`indicator_snapshots` 表从未写入、无持仓与权益快照）。因此 **R1–R3 未补齐前不得进入全自动闭环阶段**。

**与 PoC 现有设计的已知冲突（须一并处理）：**

| 冲突点 | 现状 | 冲突说明 |
|--------|------|----------|
| 授权模型 | `LLM_AUTO_EXECUTE` 是**进程级**布尔（`agent/config.py:28`） | 该开关无法表达"某目标全权、另一目标不全权"；需由会话级授权取代，迁移期要定优先级 |
| "Supervisor" 名不符实 | `agent/graph/supervisor.py:80-94` 是写死的线性图，路由为 Python 函数 | 没有编排者这一层，经理层需新建 |
| 目标与进度 | 无目标概念、无持仓、无真实盈亏 | 无法计算"离目标还差多少" |
| 决策依据 | `fetch_market_node` 直连 ccxt，未接数据面 | 经理缺少"看历史"的能力 |
| 决策记录 | 只存 LLM 的输出，不存它的输入 | 归因不成立（ADR-019 证据 A1–A6） |

## 3. 功能需求

### 3.1 PoC 功能（P0）

| 功能 | 描述 |
|------|------|
| **币安 Demo 现货对接** | REST 下单/查余额 + WebSocket 行情（ccxt 或 python-binance） |
| **LLM 自主决策 Agent** | LangGraph：Supervisor → Analysis(LLM) → Risk → Execute |

| **交易日志** | 记录：时间、方向、价格、数量、LLM 决策理由、风控结果 |
| **Agent 状态持久化** | LangGraph SQLite Checkpointer |

| 半自动模式 | 信号推送 → 用户确认 → 风控 → 执行 |

| 合约 API | U 本位 + 币本位 |
| 告警通知 | Telegram Bot |
| 模拟→实盘门禁 | 24h+ 模拟验证达标检查 |

## 4. 核心业务流程

### 4.1 PoC 主流程（LLM 自主 + 全自动）

```
启动 Agent → 采集 Demo 现货行情（WebSocket/REST）
→ Analysis Agent（DeepSeek / Ollama，按 LLM_PROVIDER）分析 → 输出 BUY / SELL / HOLD + 理由 + 置信度
→ 若 HOLD：等待下一周期
→ 若 BUY/SELL 且 LLM_AUTO_EXECUTE=true：
    → Risk Agent（单笔上限 + 日亏损检查）
    → 通过 → Execute Agent 在 Demo 现货下单
    → 记录日志 + Checkpointer 持久化
→ 直至完成至少 1 买 + 1 卖 → PoC 验收
```

### 4.2 MVP 半自动流程（PoC 不做）

```
LLM/策略 产生信号 → 推送 Web 前端 → 用户确认/拒绝
→ 确认 → Risk Agent → Execute Agent → 日志
```

### 4.3 风控流程（PoC 最小版）

```
LLM 产出交易信号
  → ① 单笔金额 ≤ MAX_TRADE_AMOUNT？
  → ② 当日累计亏损 < DAILY_LOSS_LIMIT？
  → 任一拒绝 → 记录原因，不下单
  → 全部通过 → 执行
```

## 5. 技术架构概要

```
┌─────────────────────────────────────────┐
│  PoC：CLI / curl → FastAPI (127.0.0.1)  │
├─────────────────────────────────────────┤
│  LangGraph Supervisor                   │
│    → Analysis Agent (DeepSeek API 默认可切换 Ollama) │
│    → Risk Agent (2 条规则)               │
│    → Execute Agent (Demo 现货 ccxt)      │
├─────────────────────────────────────────┤
│  SQLite + LangGraph SqliteSaver         │
│  内存/文件行情缓存                        │
└─────────────────────────────────────────┘
         │ REST/WSS                │ HTTPS / HTTP
         ▼                         ▼
   币安 Demo 现货         DeepSeek API（默认）或 Ollama（切换）
```

**MVP 扩展：** + React 前端 + PostgreSQL/TimescaleDB + Redis + 策略模板 + 完整风控。

## 9. 术语表

| 术语 | 说明 |
|------|------|
| PoC | Proof of Concept，概念验证 |
| Demo Mode | 币安官方模拟交易（`demo-api.binance.com`） |
