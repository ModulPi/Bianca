## 1. 产品概述

### 1.1 产品定位

FnAgent 是一个**面向 C 端用户的加密货币自动交易 Agent 平台**，基于币安（Binance）交易所，覆盖**现货、U 本位合约、币本位合约**全品种，帮助用户通过 AI 辅助的自动化交易策略实现数字资产管理。

核心差异化：**策略模板 + AI 分析建议 + 信号跟单** 三者融合的混合决策模式，用户可自主选择全自动或半自动执行，降低普通用户的交易门槛。

### 1.2 目标用户

| 用户画像 | 特征 | 核心诉求 |
|----------|------|----------|
| 初级散户 | 交易经验 < 1 年，资金量小 | "帮我自动赚钱，不用盯盘" |
| 进阶玩家 | 有一定交易经验，有自己的策略思路 | "把我的策略交给 Agent 自动执行" |
| 跟单用户 | 不想自己分析，愿意跟随信号 | "跟着高手/信号走" |

### 1.3 核心价值主张

- **零门槛自动化**：无需编程，配置策略参数即可运行
- **AI 辅助决策**：LLM 分析市场行情，提供决策参考
- **风险可控**：内置多层风控，支持模拟交易先行验证
- **透明可审计**：每笔交易的决策过程可回溯

## 2. 市场背景与竞品参考

### 2.1 行业现状

- 币安、Gate.io、Kraken、Bitget 等主流交易所均已推出 AI 交易产品
- 多智能体（Multi-Agent）架构是主流趋势：分析→决策→执行→风控各司其职
- 开源生态活跃（OpenClaw、nof1.ai 等框架）
- 行业从"规则式机器人"向"AI 自主决策 Agent"演进

### 2.2 竞品参考

| 产品 | 类型 | 核心能力 | 参考价值 |
|------|------|----------|----------|
| 币安 Ai Pro | 交易所官方 | 自然语言→交易执行，$9.99/月 | 产品形态参考 |
| Bitget GetAgent | 交易所官方 | 工作流编排，58个工具，百万用户 | 功能广度参考 |
| nof1.ai | 开源 | LLM自主决策，Gate.io合约 | 架构参考 |
| 币安现货网格 | 交易所内置 | 参数化网格交易 | 策略模板参考 |

### 2.3 FnAgent 差异化方向

- **混合决策 + 可配置执行模式**：用户可选策略模板 / AI 分析 / 跟单，每个策略可独立配置为「全自动执行」或「AI 建议 + 人工确认」
- **模拟先行**：所有策略必须先通过模拟交易验证，才能开启实盘
- **全品种覆盖**：现货 + U 本位合约 + 币本位合约，一套系统统一管理
- **本地 LLM 优先**：默认 Ollama 本地模型，保护隐私、零成本，也可切换云端 LLM
- **开源 + 自部署**：MIT 协议开源，用户 Docker Compose 一键部署，数据完全自控
- **多语言架构**：Python 做 Agent 核心和交易所对接，TypeScript/React 做前端，后期 Go/Rust 做高性能数据处理

## 5. 核心业务流程

### 5.1 主流程：策略交易

```
用户部署 → 配置 API Key → 选择策略模板 → 设置参数 + 风控
→ 选择执行模式（全自动 / AI 建议+人工确认）
→ 模拟交易验证（必须） → 模拟表现达标 → 开启实盘
→ Agent 持续运行：行情采集 → 策略决策 → 风控审核 → [人工确认(可选)] → 下单执行 → 日志记录
→ 用户随时查看持仓/收益/决策日志
```

### 5.2 LLM 辅助决策流程

```
定时触发 → 采集多时间框架数据（1m/5m/15m/1h/4h）
→ LLM 分析（技术面+情绪面+新闻事件）
→ 生成分析报告 + 交易建议（标注置信度）
→ 用户查看报告，确认/拒绝/修改建议
→ 确认后 → 风控审核 → 下单执行 → 记录决策理由
```

> **关键约束：** LLM **不直接**决策下单，只输出分析和建议。最终执行权在用户（半自动模式）或策略规则引擎（全自动模式）。

### 5.3 风控流程（每次交易必经，不可绕过）

```
策略/LLM/跟单 生成交易信号
  → 风控层强制检查：
    ① 止损是否触发？
    ② 仓位是否超限？（单币种上限 / 总持仓上限）
    ③ 日亏损是否达标？
    ④ 合约额外：杠杆是否超限？
    ⑤ 回撤是否触发熔断？
    → 任一拒绝 → 记录原因 + 推送通知
    → 全部通过 → 执行层下单 → 监控订单状态 → 成交/失败处理
```

> **PoC 特殊说明：** MVP 阶段仅服务开发者本人，暂不需要多用户注册/登录系统和 KYC。

## 6. 技术架构概要（非详细设计）

```
┌─────────────────────────────────────────────────┐
│              前端层 (React + TypeScript)          │
│        Web 控制台 / PWA 响应式                    │
│        MVP 后期：React Native 移动端              │
├─────────────────────────────────────────────────┤
│              API 网关层 (Python/FastAPI)          │
│          REST API + WebSocket                    │
├──────────┬──────────┬──────────┬────────────────┤
│ 策略引擎  │ LLM 分析  │ 风控服务  │ 通知服务        │
│ (Python)  │ (Python)  │ (Python)  │ (Python)       │
├──────────┴──────────┴──────────┴────────────────┤
│          Agent 编排核心 (Python/LangGraph)        │
│    ├─ 策略 Agent（规则引擎 + 参数化模板）         │
│    ├─ 分析 Agent（LLM: Ollama 本地优先）         │
│    ├─ 执行 Agent（币安 API 现货+合约）           │
│    └─ 风控 Agent（规则引擎，不可绕过）            │
├─────────────────────────────────────────────────┤
│        交易所接口层 (Python/ccxt)                 │
│    ├─ 现货 REST API + WebSocket                  │
│    ├─ U 本位合约 API                              │
│    └─ 币本位合约 API                              │
├─────────────────────────────────────────────────┤
│              数据层                               │
│    PostgreSQL + TimescaleDB（交易记录/K线/时序）  │
│    Redis（行情缓存、WebSocket 会话）              │
│    Ollama（本地 LLM）                            │
├─────────────────────────────────────────────────┤
│           部署：Docker Compose 单机               │
└─────────────────────────────────────────────────┘
```

**关键设计原则：**

1. **策略 — 风控 — 执行 三层分离**（行业最佳实践，风控是不可绕过的最后防线）
2. **所有策略必须先模拟验证，才能实盘**
3. **LLM 只做分析和建议，不直接下单**（B 模式：AI 建议 → 人工确认 → 执行）
4. **用户可配置执行模式**：每个策略可选「全自动」（规则引擎直接执行）或「半自动」（AI 建议需人工确认）
5. **API Key AES-256 加密存储**，建议用户开启 IP 白名单
6. **多语言混合**：Python（Agent 核心 + 交易所）+ TypeScript/React（前端）+ Go/Rust（后期高性能数据处理）
7. **开源 MIT + Docker Compose 一键部署**，数据完全自控

## 8. PoC 阶段里程碑

| 里程碑 | 目标 | 预计产出 |
|--------|------|----------|
| **M0：环境搭建** | 币安测试网连通，Docker Compose 一键启动 | 能调用币安 API 查询余额、获取行情（现货+合约） |
| **M1：策略引擎** | 1 个策略模板（网格交易）在模拟环境 7×24 运行 | 自动下单、持仓管理、基础日志；支持全自动和半自动两种模式 |
| **M2：风控集成** | 三层分离架构生效：策略→风控→执行 | 止损止盈、仓位限制、日亏损熔断，风控拦截 case 可验证 |
| **M3：LLM 分析** | Ollama 本地模型接入，定时生成分析报告 | 多时间框架 K 线分析 + 交易建议（仅建议，不自动执行） |
| **M4：Web 控制台** | React 前端上线 | 配置策略参数、查看持仓/收益/K 线、查看 AI 分析报告 |

### 里程碑依赖关系

```
M0（环境+API 连通）
  └→ M1（策略引擎）──→ M2（风控集成）
                                └→ M3（LLM 分析）
                                          └→ M4（Web 控制台）
```

> M1 和 M2 是核心路径，M3 和 M4 可以并行开发。
